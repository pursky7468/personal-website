Claude Code 有個 Remote Control（`/rc`）：在終端機的對話裡打 `/rc`，就能從手機上的 Claude app 接手同一個對話。出門在外看進度、回個問題、叫它繼續做，都很方便。

但它有個前提：**`/rc` 得在電腦前打。**

已經開著的對話沒問題。麻煩的是我人在外面、想開一個**新的**對話做另一件事——新對話會開在電腦的終端機裡，沒有人去幫它打 `/rc`，手機就碰不到它。

## 解法：讓新對話一出生就在 /rc 狀態

`claude` CLI 本身就有 `--remote-control` 參數，效果等同啟動後打 `/rc`。所以缺的只是「開一個新視窗、在指定目錄跑這行」的那一步。我寫了一支腳本 `new-rc-session.ps1` 做這件事，核心只有幾行：

```powershell
param(
    [string]$Path = 'C:\GitSource',
    [string]$Name = ''
)

# 一律給名字，之後才能依名稱關閉
if (-not $Name) { $Name = 'rc-' + (Get-Date -Format 'yyyyMMdd-HHmmss') }

# 整條指令組成單一字串：PS 5.1 會靜默丟掉空字串的 native 參數
$cmd = "claude --remote-control '" + ($Name -replace "'", "''") + "'"

Start-Process powershell -WorkingDirectory $Path -ArgumentList '-NoExit', '-Command', $cmd
```

實際用起來的流程是：

1. 手機上打開某個**已經在 /rc 狀態**的對話
2. 跟它說「開個新對話，目錄在 X」
3. 它在電腦上跑這支腳本 → 跳出一個新視窗，裡面的 Claude Code 已經是 Remote Control 模式
4. 新對話註冊好後（要等幾秒）就會出現在手機 app 的清單裡，直接點進去用

換句話說，**只要電腦上留著一個 /rc 對話，它就是我從手機開新對話的入口。**

## 一個坑：PowerShell 5.1 會靜默吃掉空參數

直覺的寫法是把參數一個個分開傳給外部程式。但 Windows PowerShell 5.1 呼叫 native exe 時，遇到空字串參數會**直接丟掉**——不報錯、不警告，`claude` 收到的參數就跟你以為的不一樣。

解法是把整條指令先組成**一個字串**再交給 `-Command`，同時把名稱裡的單引號跳脫掉。這類「沒有錯誤訊息、只是結果不對」的故障最難查，所以我在腳本裡留了一行註解給未來的自己。

## 為什麼一定要給名字

腳本在你沒指定名稱時，會自動命名成 `rc-20261021-143005` 這種格式。設計上的考量是：**開得出來，就要關得掉**。

從手機開了幾個對話之後，電腦上會累積好幾個 `claude.exe`。我實測過，不帶名稱啟動的 RC 對話，在 `close-session.ps1` 的清單上名稱欄是空的，只能靠 PID 和啟動時間辨識——要關的時候很容易關錯。

所以我配了另一支 `close-session.ps1`：

- `-List` 列出本機所有 Claude Code 對話（PID、名稱、模式、狀態、啟動時間）
- `-Name` 或 `-Id` 指定要關哪一個
- 安全規則寫死在腳本裡：**不關自己所在的那個對話**、目標必須是 `claude.exe`、名稱必須**恰好比對到一個**，否則什麼都不關

讓 AI 去關程序這件事，我寧可它多拒絕幾次，也不要猜錯一次。

## 小結

整件事很小：一個 CLI 參數、一個新視窗、一個自動命名。但它把「每開一個新對話都得人在電腦前」這個限制拿掉了——只要電腦開著、留著一個 /rc 對話，人在哪裡都能開新的工作線。

幾點心得：

- **先找現成參數。** 不需要模擬鍵盤去打 `/rc`，CLI 本來就支援 `--remote-control`。
- **開得出來就要關得掉。** 自動命名是為了關閉而設計的，不是為了好看。
- **給 AI 用的破壞性操作，安全檢查要寫在腳本裡**，而不是寫在提示詞裡期待它遵守。

## 後記：官方其實有 server mode

這篇有個前提我沒寫清楚：**第一個 /rc 對話還是得人在電腦前開。** 我不確定有沒有更有效率的做法，所以發文後回頭查了官方文件，結果真的有。

[Remote Control 官方文件](https://code.claude.com/docs/en/remote-control)寫了 server mode：在電腦上跑 `claude remote-control`，它會常駐等待連線，**不需要先開一個互動對話**。文件說它會接受 on-demand 的多個並行 session，我的理解（推論）是可以從 Claude app 直接開新 session。預設最多 32 個並行 session，還可以用 `--spawn worktree` 讓每個 session 各用一個 git worktree。我在本機（Claude Code 2.1.306）跑 `claude remote-control --help` 確認過，這些選項都在。

要先說清楚：**從手機直接開新 session 這段，我還沒實測**，目前的依據只有文件。

兩者的差別，依文件和我的腳本整理：

| | 我的腳本 | 官方 server mode |
|---|---|---|
| 要先在電腦前開對話 | 要（第一個 /rc 對話） | 不用（但要先在電腦上把 server 跑起來） |
| 新 session 的工作目錄 | 每次可以指定任意目錄 | 跟著 server 啟動的目錄（或它底下的 worktree） |
| 同時開多個 | 每個都是獨立視窗、獨立 process | 一個 server 管多個 session |

文件另外寫了幾個限制：第一次在某個目錄跑要互動確認 trust；斷線約 10 分鐘 server 會退出。這篇正文的三點心得，第一點「先找現成參數」反而在我自己身上應驗了：我找到了 `--remote-control`，卻沒往下多看一層。
